2. Function, type và layer

Hàm nên có một trách nhiệm, input/output rõ, ít side effect:

from decimal import Decimal

def net_amount(quantity: int, price: Decimal, discount: Decimal) -> Decimal:
    if quantity <= 0:
        raise ValueError("quantity must be positive")
    return quantity * price - discount

Type hint giúp đọc/static check nhưng không tự validate runtime. Dùng Decimal cho tiền khi cần chính xác. Tách transport (API), service (business rule), repository (data access); truyền dependency vào thay vì tạo cứng bên trong để dễ test.

3. Exception và resource lifecycle

  • Raise exception có ý nghĩa; catch ở layer có thể xử lý hoặc thêm context.
  • Giữ nguyên nguyên nhân bằng raise ... from exc.
  • Không except Exception: pass.
  • Không trả stack trace/SQL/secret cho client.
  • Retry có giới hạn cho timeout/network/rate limit; validation/auth thường không retry.

Dùng context manager cho file/connection. Database transaction cần commit/rollback rõ. HTTP/database pool thường sống theo application lifecycle, không tạo pool mới cho mỗi request.

4. Config và secret

  • Config thay đổi theo môi trường, không hard-code trong business logic.
  • Environment variable/typed settings cho runtime config.
  • Secret manager cho token/password; .env local phải bị ignore.
  • Validate config khi app start để fail rõ.
  • Không log giá trị secret hoặc raw PII.

5. Sync, async và concurrency

async hữu ích khi chờ nhiều I/O, không tự làm CPU work nhanh. Không gọi thư viện blocking lâu trong event loop. Luôn có timeout, concurrency limit và backpressure khi gọi downstream. Chọn sync nếu workload đơn giản và code rõ hơn.

6. Logging và test

Log có timestamp, severity, correlation ID và context; production không phụ thuộc vào print.

  • Unit test pure business logic.
  • Integration test database/API boundary.
  • Mock hệ thống bên ngoài, không mock mọi implementation detail.
  • Test happy path, boundary và failure path.
def test_net_amount():
    assert net_amount(2, Decimal("10"), Decimal("1.5")) == Decimal("18.5")

7. Bài thực hành và checklist

Tạo ứng dụng order nhỏ: router/service/repository, config qua environment, input validation, custom exception, transaction/context đúng, structured log và unit/integration tests.

  • Dependency cô lập và tái lập được.
  • Business logic tách khỏi I/O/transport.
  • Exception có context, resource luôn đóng.
  • Secret không hard-code/log/commit.
  • Có timeout, validation và test failure path.

8. Python object model ở mức cần thiết

  • Biến giữ reference tới object, không phải "hộp chứa giá trị" độc lập.
  • List/dict là mutable; string/tuple/int là immutable.
  • Default argument được tạo một lần khi định nghĩa hàm, vì vậy tránh def f(items=[]).
def add_item(item: str, items: list[str] | None = None) -> list[str]:
    result = [] if items is None else list(items)
    result.append(item)
    return result

Copy nông chỉ tạo container mới; object lồng nhau vẫn dùng chung reference. Đây là nguồn bug khi sửa config/dict dùng lại giữa request.

9. Dependency injection bằng ví dụ

from typing import Protocol

class OrderRepository(Protocol):
    def get(self, order_id: int) -> dict | None: ...

class OrderService:
    def __init__(self, repository: OrderRepository):
        self.repository = repository

    def require_order(self, order_id: int) -> dict:
        order = self.repository.get(order_id)
        if order is None:
            raise OrderNotFound(order_id)
        return order

Service chỉ phụ thuộc vào contract nhỏ. Unit test có thể dùng fake repository trong memory; production truyền repository kết nối database.

10. HTTP client đáng tin

import httpx

timeout = httpx.Timeout(connect=2.0, read=5.0, write=5.0, pool=1.0)
with httpx.Client(timeout=timeout) as client:
    response = client.get(url)
    response.raise_for_status()

Phân biệt connect/read timeout để biết đang kẹt ở đâu. Retry GET thường an toàn hơn POST; POST chỉ retry khi API có idempotency key hoặc contract tương đương. Đặt concurrency limit để không tự tạo "thundering herd" khi downstream phục hồi.

11. Transaction boundary

Một use case nghiệp vụ nên xác định transaction boundary rõ:

create order -> reserve stock -> save order -> commit

Không giữ database transaction mở trong lúc chờ HTTP lâu nếu tránh được. Nếu quy trình đi qua nhiều service, không thể dùng một transaction database chung; cần saga/compensation, outbox hoặc trạng thái trung gian tùy bài toán.

12. Test theo Arrange–Act–Assert

def test_missing_order_raises():
    # Arrange
    repository = FakeOrderRepository({})
    service = OrderService(repository)

    # Act + Assert
    with pytest.raises(OrderNotFound):
        service.require_order(999)

Test hành vi public, không khóa chặt vào private method. Với thời gian, random và network, truyền dependency/fake clock để test deterministic.

13. Câu hỏi tự kiểm tra có đáp án

  1. Type hint có chặn string truyền vào tham số int không? Không tự động; cần static checker hoặc runtime validation.
  2. Vì sao không tạo DB connection cho từng query? Tốn handshake và dễ cạn connection; dùng pool theo lifecycle.
  3. Khi nào async có lợi? Nhiều tác vụ I/O chờ đợi và thư viện toàn tuyến hỗ trợ non-blocking.
  4. Vì sao business logic nên gần pure function? Dễ hiểu, test nhanh và không phụ thuộc môi trường.
