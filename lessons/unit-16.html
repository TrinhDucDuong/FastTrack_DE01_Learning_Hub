DataOps & CI/CD for Data Pipelines

Tự động hóa test, promotion, migration và recovery cho code lẫn data.

DataOpsCI/CDMigrationRollback

Trong bài này

1. DataOps là gì?

DataOps áp dụng tư duy engineering và vận hành vào vòng đời dữ liệu: version control, automated test, CI/CD, observability, collaboration và cải tiến liên tục. Mục tiêu là giao dữ liệu nhanh hơn nhưng vẫn đáng tin và truy vết được.

Plan -> Code -> Review -> Test -> Deploy -> Observe -> Learn

2. Những gì phải version control

  • Pipeline/DAG, SQL/dbt, Spark/Python code.
  • Schema contract, test, configuration không nhạy cảm.
  • Infrastructure as Code.
  • Dashboard/semantic model nếu công cụ hỗ trợ.
  • Migration và release note.

Không commit secret, access key, personal data hay output dataset lớn.

3. CI pipeline

Mỗi pull request nên chạy nhanh từ rẻ đến đắt:

  1. Format/lint và secret scan.
  2. Unit test transformation.
  3. Validate/compile DAG, dbt, IaC.
  4. Schema/contract test.
  5. Integration test trên dữ liệu nhỏ và môi trường cô lập.
  6. Data quality + idempotency test.
  7. Build artifact/image bất biến.

CI thất bại phải chặn merge cho control bắt buộc. Test data cần nhỏ, deterministic và không chứa PII production.

4. CD và promotion

Build một artifact rồi promote qua môi trường, tránh build lại code khác nhau:

dev -> test/staging -> production
          approval      canary/controlled release

Config/secret thay theo environment; artifact/code giữ nguyên. Production deployment có approval cho thay đổi rủi ro, audit trail và kế hoạch rollback/roll-forward.

5. Database và data migration

Schema/data thay đổi khó rollback hơn stateless app vì dữ liệu đã được ghi. Dùng pattern tương thích:

  1. Expand: thêm cột/bảng mới, downstream cũ vẫn chạy.
  2. Backfill và validate.
  3. Chuyển producer/consumer sang phiên bản mới.
  4. Contract: xóa phần cũ sau thời gian deprecation.

Không rename/drop trực tiếp nếu chưa kiểm tra lineage và consumer. Migration phải idempotent hoặc có trạng thái rõ.

6. Test pyramid cho data

  • Nhiều unit/schema test nhanh.
  • Ít integration/end-to-end test nhưng bao phủ critical path.
  • Reconciliation test source vs target.
  • Regression test KPI bằng golden dataset.
  • Performance/cost test cho query/job quan trọng.
  • Recovery test: retry, rerun, backfill, restore.

Data test pass không đủ nếu code không chạy đúng lịch; platform test pass không đủ nếu KPI sai.

7. Deployment strategy

  • Rolling: thay dần compute/workers.
  • Blue-green: hai môi trường, chuyển traffic sau verify.
  • Canary: chạy cho một phần data/workload.
  • Shadow/dual run: pipeline mới chạy song song, so sánh output trước cutover.

Với transformation quan trọng, dual run + reconciliation thường an toàn: so row count, key, aggregate và sample record giữa legacy/new.

8. Rollback và data recovery

Rollback code không tự rollback dữ liệu đã ghi. Cần tách:

  • Code rollback/roll-forward.
  • Table/version restore hoặc snapshot.
  • Recompute partition/window bị ảnh hưởng.
  • Invalidate cache/refresh downstream.
  • Ghi lại release ID và data range chịu tác động.

Ưu tiên roll-forward khi migration không thể đảo an toàn. Mọi kế hoạch phải được thử trước production.

9. Branch và environment

  • Branch ngắn, pull request nhỏ, review được.
  • Developer có schema/database riêng hoặc ephemeral environment.
  • Tên resource deterministic theo env/branch và có cleanup TTL.
  • Protected production branch/environment.
  • Service identity cho automation, không dùng account cá nhân.

10. Bài thực hành

Thiết kế pipeline CI/CD cho project dbt + Airflow:

  • PR: lint, parse DAG, dbt build trong schema tạm, unit/data test.
  • Merge: tạo artifact/version và deploy staging.
  • Staging: chạy sample/backfill nhỏ, reconciliation.
  • Approval: deploy production.
  • Post-deploy: smoke test, freshness/quality monitor.
  • Rollback: chỉ rõ code và data recovery khác nhau thế nào.

11. Checklist

  • Build artifact một lần và promote.
  • Môi trường/credential tách biệt.
  • Test gồm code, contract, data và rerun.
  • Migration backward-compatible và có lineage impact analysis.
  • Có audit, approval, post-deploy verify và data-aware rollback.

12. CI pipeline mẫu theo stage

validate
  -> format/lint + secret scan + dependency scan
unit
  -> Python/SQL macro tests
compile
  -> dbt compile + Airflow parse + IaC validate
integration
  -> ephemeral schema/resources + sample data
quality
  -> contracts + data tests + reconciliation + rerun test
package
  -> immutable image/artifact + manifest/SBOM

Stage rẻ/chạy nhanh đặt trước để feedback sớm. Cache dependency có kiểm soát; không cache output có thể làm test stale.

13. Environment isolation

Mỗi PR có schema như ci_pr_123, service identity giới hạn và cleanup TTL. Test không đọc/ghi production. Nếu dùng production metadata/artifact để defer, credential vẫn chỉ read cần thiết.

14. Schema migration expand-contract

Ví dụ đổi customer_name thành full_name:

  1. Expand: thêm full_name, producer ghi cả hai hoặc view compatibility.
  2. Backfill full_name; test null/count/equality.
  3. Migrate consumers; theo dõi usage cột cũ.
  4. Announce deprecation deadline.
  5. Contract: xóa cột cũ trong release riêng sau khi zero consumer.

Đây là thay đổi nhiều release, không phải một ALTER TABLE RENAME tức thời.

15. Golden dataset và regression

Golden dataset nhỏ nhưng chứa edge case: duplicate, null, late event, refund, timezone boundary, SCD change. Expected output được review. Khi logic đổi có chủ đích, cập nhật expected cùng lý do nghiệp vụ; không chấp nhận snapshot mới chỉ để test xanh.

16. Deployment verification

Sau deploy:

  • Smoke run một interval nhỏ.
  • Xác nhận code/artifact version trong log.
  • Chạy schema + critical data tests.
  • So metrics với baseline: rows, duration, cost, errors.
  • Quan sát ít nhất một schedule nếu rủi ro cao.
  • Có decision rollback/continue rõ.

17. Supply chain và dependency

Pin/lock dependency, scan vulnerability/license theo policy, build từ trusted runner và ký/ghi checksum artifact khi phù hợp. Không cài package tùy ý trực tiếp trên worker production.

18. Câu hỏi có đáp án

  1. CI pass có đảm bảo production data đúng? Không; cần post-deploy data validation/monitoring.
  2. Vì sao build once promote many? Giảm khác biệt artifact giữa môi trường và tăng traceability.
  3. Rollback luôn tốt hơn roll-forward? Không; data migration đã ghi có thể không đảo an toàn.
  4. E2E test càng nhiều càng tốt? Không; chậm/flaky. Dùng test pyramid và một số critical paths.
